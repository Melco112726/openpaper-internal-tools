# 故障排查

先判断故障发生在哪个阶段，再做最小干预。不要通过关闭整机安全防护、重复高速点击或强制终止正在保存的任务来“解决”问题。

## 一、OpenPaper

### 1. 双击后没有页面

1. 等待 10–20 秒。
2. 手动打开 `http://127.0.0.1:8787/`。
3. 检查任务管理器中是否已有 `OpenPaper.exe`。
4. 检查 8787 端口是否被其他程序占用。
5. 若安全软件拦截，记录产品名称和提示；不要直接关闭整机防护。

### 2. 页面一直显示“正在检查”

- 确认后台进程仍在运行；
- 强制刷新页面；
- 避免代理扩展代理 `127.0.0.1`；
- 地址必须是本机 HTTP，不要改成局域网 IP 或 HTTPS。

### 3. 英文本地结果太少

- 放宽年份和文献类型；
- 减少必须同时满足的概念组；
- 增加同义词、拼写变体和上位词；
- 先做高召回检索，再在第二阶段筛选；
- 需要语义扩展时，另开一轮 Undermind 深搜。

### 4. Undermind 无法连接

- 核对 workspace 是否属于自己的账户；
- 重新完成 OAuth；
- 确认没有误启旧版 Codex 桥接器；
- 检查外部服务和网络；
- 直接切回 Crossref + OpenAlex 不会破坏本地项目。

### 5. 知网停在登录或验证码

- 只在 OpenPaper 打开的专用浏览器中处理；
- 完成后回到工作台点击继续；
- 如果当前不是结果页，允许程序重新提交本轮条件；
- 自动读取仍失败时使用题录导入；
- 不要把账号密码、Cookie 或验证码发给维护者。

### 6. 中文结果没有 DOI

这是正常情况。OpenPaper 可以用 CNKI 身份或题名指纹保存和去重；只有 DOI 型 OA 流程会受限。

### 7. 图谱作者或引用不足

公开元数据不一定完整。显示“待核验”时应打开来源或 PDF；虚线语义关系不能替代真实引用。

### 8. 全文一直未获取

- 核对 DOI；
- 打开原始来源；
- 检查 Unpaywall 邮箱和外部网络；
- 检查学校/机构权限；
- 导出缺失 DOI 并交给 DoiRescue；
- 不要把“未获取”理解为“应该排除”。

### 9. 重启后项目显示未完成

任务中途关闭时，OpenPaper 会把旧的“运行中”快照回收为“未完成”。打开项目检查已经保存的候选；必要时重新提交当前阶段。

## 二、DoiRescue

### 1. 所有 DOI 一次性失败

检查日志中是否出现：

- Unpaywall 422；
- `publisher_auto_inference_failed`；
- `unsupported_publisher`；
- Worker 找不到或无法启动。

当前版本应先逐 DOI 建立 provider plan，不再把混合出版社整体交给 `--publisher auto`。若仍出现整批相同错误，应导出 `provider-plan.json` 和脱敏日志。

### 2. Unpaywall 422 或空邮箱

打开设置：

- 填写本人有效联系邮箱；或
- 明确选择跳过 Unpaywall。

邮箱为空时当前版本不会发送 `?email=`。不要编造他人邮箱。

### 3. Unpaywall 连接超时

连接超时属于网络/外部服务错误，不代表文献不存在。

- 等待有限重试结束；
- 检查代理、DNS 和 HTTPS 连接；
- 选择跳过 Unpaywall后继续其他 OA 路线；
- 不要反复高速点击“开始下载”。

### 4. 显示“需要机构访问”

这表示出版社已识别，但 OA 阶段没有成功。

1. 设置机构中英文名称；
2. 启用机构访问；
3. 点击“使用机构权限”；
4. 在可见浏览器中自行完成登录与验证；
5. 回到 DoiRescue观察当前篇状态。

### 5. 机构列表没有自己的学校

- 关闭或跳过当前页面；
- 不要在错误机构下登录；
- 将该文献转入人工处理；
- 使用 DOI 官方页、图书馆发现系统、馆际互借或作者渠道；
- 记录 `institution_not_available` 等人工原因。

一个学校不在某出版社身份提供商列表中，不代表 DOI 不存在。

### 6. 关闭浏览器后程序仍“处理中”

先等待当前篇的退出检测和硬超时。随后可以：

- 点击“跳过当前篇”；
- 点击“重试当前篇”；
- 点击“停止全部”。

当前版本按单篇 Worker 运行，浏览器退出不应永久阻塞整批。若按钮无效，记录当前 DOI、出版社、操作时间和脱敏后的最后日志行。

### 7. “停止全部”后仍有进程

DoiRescue 会停止当前 Worker 和它启动的后代进程，但不会按名称关闭所有 Chrome/Node。

- 等待几秒让进程树回收；
- 检查是否是用户自己打开的日常浏览器；
- 不要手动结束无关的 Chrome/Edge；
- 重启软件后可从 manifest 恢复批次。

### 8. 为什么不能同时打开多个机构网页

当前 InstSci/CloakBrowser 会共享专用 Profile，免费环境也固定单会话。并行窗口可能造成登录态、验证码、下载文件和停止动作互相干扰。因此机构任务固定并发 1。

### 9. 登录后仍反复要求登录

- 确认启用了会话复用；
- 检查 Profile 状态是否“已创建”；
- 确认机构或出版社没有让会话过期；
- 在设置中打开机构登录浏览器并重新登录；
- 不要手动复制 Cookie 到配置文件。

### 10. 需要人工处理

打开人工队列：

1. 先打开 DOI 官方页面；
2. 有可信出版社地址时再打开出版社页；
3. 手动下载后选择本地 PDF；
4. 查看匹配置信度；
5. 对低置信度文件人工核对后再确认；
6. 无法处理时填写原因并跳过。

### 11. 选择的文件不是 PDF 或已损坏

文件不会进入成功区。无效候选会复制到 `quarantine`，原文件仍保留。重新下载正确 PDF 后再次关联。

### 12. PDF 显示低匹配或未知

- `low`：未找到 DOI，题名关键词匹配很少；
- `unknown`：扫描件或文件没有可直接搜索的文本；
- `medium`：只匹配部分题名；
- `high`：包含目标 DOI 或大部分题名词。

低或未知不必然表示错误，但必须由用户打开 PDF 核对题名、作者、年份和期刊。

### 13. Worker 缺失

确认以下目录同级：

```text
DoiRescue\DoiRescue.exe
instsci-worker\instsci-worker.exe
```

不要只把 `DoiRescue.exe` 复制到桌面。应保留完整解压目录，桌面只创建快捷方式。
