# OpenPaper 完整使用指南

适用版本：`0.2.0-internal.2`，Windows 10/11 x64 封闭内测版。

## 1. 产品定位

OpenPaper 负责一条完整且可恢复的本地研究链：

```text
提出问题 → 英文/中文发现 → 统一候选 → 人工复核
         → 关系图谱 → 全文获取 → 缺失清单 → 保存续作
```

它遵循三条原则：

1. **本地优先**：项目、设置、缓存、日志和下载默认保存在当前 Windows 用户目录。
2. **人工判断优先**：推荐、相关度、翻译和图谱只辅助判断，不替研究者决定纳入。
3. **保留来源差异**：开放索引、Undermind、知网、OA 与其他来源始终保留来源标记。

## 2. 安装与启动

1. 从 GitHub Release 下载 OpenPaper ZIP。
2. 完整解压到普通本地目录，例如 `D:\OpenPaper-v0.2.0-internal.2\`。
3. 不要只复制 `OpenPaper.exe`；它依赖同目录 `_internal`。
4. 双击 `OpenPaper.exe`。
5. 等待浏览器打开 `http://127.0.0.1:8787/`。

发布包已经包含 Python 运行时。应用只监听 `127.0.0.1`，不作为局域网服务开放。

关闭浏览器标签通常不会停止后台进程。需要完全退出时，应先等待任务保存或下载结束，再从任务管理器结束 `OpenPaper.exe`。

## 3. 首次设置

首次运行建议使用最小配置：

| 设置项 | 首次建议 | 用途 |
|---|---|---|
| 默认检索 | 本地检索 | 使用 Crossref 与 OpenAlex 建立英文基线 |
| Undermind workspace | 留空 | 需要语义/引文深搜时再填写自己的 workspace |
| OpenAlex API key | 可留空试用 | 稳定使用时建议配置自己的 Key |
| Unpaywall 邮箱 | 可留空 | 作为 Unpaywall API 联系方式，留空时跳过 |
| 知网浏览器 | 自动选择 | Edge 优先，必要时可固定 Chrome |
| 旧版 Codex 桥接器 | 关闭 | 仅为兼容场景保留 |
| Sci-Hub 个人兼容回退 | 关闭 | 新安装默认关闭 |

普通用户不需要手动提取 OAuth Token。Undermind 连接通过可见系统浏览器完成 OAuth 2.0 + PKCE；令牌使用当前 Windows 用户的 DPAPI 保护。

不要把 OpenAlex Key、完整 workspace、邮箱、Token、Cookie 或知网浏览器 Profile 放入截图、日志反馈或 GitHub。

## 4. 第一次练习

正式课题前建议先做一个小闭环：

1. 选择“找文献 / 列文献清单”。
2. 只启用英文通道和本地检索。
3. 填写边界清楚的主题。
4. 返回数量设为 10–20，年份设为最近 5–10 年。
5. 运行检索并在第二阶段保留 2–3 篇。
6. 用 1–2 篇构建图谱。
7. 把选中文献交给第三阶段获取 PDF。
8. 打开项目库，确认状态可以恢复。

## 5. 构造可检索的问题

研究主题应包含“对象 + 核心现象/变量 + 必要情境”，不要把全部纳入标准塞在一行。

核心概念组中：

- 同一行的同义表达近似 OR，可用 `|` 分隔；
- 不同行近似 AND，连接不同概念维度；
- 方法词通常先作为复核条件，不必全部强制进入检索式。

结果为 0 时，优先放宽概念组、年份、作者或期刊限制，不要立即换题。

## 6. 第一阶段：文献发现

### 6.1 英文本地检索

Crossref + OpenAlex 是默认起点，适合：

- 建立主题的英文文献地形；
- 获得可解释、可重复的基础候选；
- 在没有外部账户时正常工作；
- 先用小结果集试验筛选规则。

初次探索建议返回 20–50 篇，只有在明确需要时再固定作者、期刊或 DOI。

### 6.2 Undermind 深度检索

Undermind 是可选增强，用于关键词难覆盖的语义近邻、引文扩展和研究空白线索。

1. 设置自己的 workspace 地址。
2. 点击连接并在系统浏览器完成 OAuth。
3. 启动前核对本次研究主题、范围和 workspace。
4. 任务完成后仍需逐篇人工复核。

深搜会写入用户自己的 Undermind workspace，并可能消耗账户额度。取消或失败不会破坏本地检索结果。

### 6.3 中文 / 知网通道

1. 启用中文通道并填写中文主题、概念组、年份和来源范围。
2. 连接知网专用浏览器。
3. 用户自行登录并完成验证码或机构认证。
4. 回到工作台启动检索。
5. 页面要求人工处理时，在浏览器完成后点击继续。
6. 自动读取失败时，从知网导出 RIS、EndNote、RefWorks 或纯文本题录再导入。

中文论文即使没有 DOI，也可凭知网数据库代码、文件名、详情页或题名—作者—年份指纹保存和去重。

### 6.4 双通道

- 英文与中文通道各自运行、各自显示进度。
- 任一路先完成，候选立即进入第二阶段。
- 后完成的通道增量合并并去重，不覆盖已有候选。
- 用户已完成的勾选、排除和删除状态不会被重置。
- 可以停止一条仍在运行的通道而保留另一条已完成结果。

研究问题应保持一致，但中英文检索式要分别适应语言与数据库字段，不必逐字对应。

## 7. 第二阶段：人工复核

系统负责找到候选，研究者负责回答：

1. 研究对象是否符合？
2. 变量、现象或机制是否真正相关？
3. 文献类型和设计是否符合用途？
4. 它是直接证据、机制证据、理论背景，还是仅关键词相似？

“推荐”不是“纳入”；机器翻译不是原始文献；公开元数据缺失时宁可显示“待核验”，也不应猜测作者。

可按语言与来源过滤，逐篇勾选、排除或删除。删除候选不会删除已经保存的 PDF。

## 8. 关系图谱

可选择 1–5 篇作为种子，或用 2–5 篇进行比较。

| 图谱元素 | 含义 |
|---|---|
| 种子 | 本轮选择的中心文献 |
| 前置 / 后续 | 时间与引文方向上的相关节点 |
| 实线 | 公开数据中可核验的直接引用 |
| 虚线 | OpenPaper 计算的本地语义相关 |
| 待探索 | 值得继续核验、尚未加入候选的节点 |

图谱适合发现共同理论来源、漏检的早期节点和不同证据分支；不应把高关联度当成高质量证据，也不应把虚线当作真实引用。

## 9. 第三阶段：全文获取

可以从复核区交接选中文献，也可从起始页直接粘贴 DOI、BibTeX 或 RIS。

正常来源优先级包括：

1. 出版社开放版；
2. 机构或学科开放仓储；
3. Unpaywall；
4. Europe PMC；
5. 预印本与其他可核验 OA 线索；
6. 当前用户通过知网账号或机构权限可以合法访问的 PDF。

只有验证为 PDF 的文件才会进入下载目录。成功后仍应打开文件核对题名、作者、年份、版本和页码。

未自动获得的文献会进入缺失清单。它代表自动流程边界，不代表文献不存在或应从研究中排除。此时可以把 DOI 清单交给 DoiRescue。

## 10. 项目库与续作

每轮检索形成独立快照，保存：

- 检索通道、表单和实际查询；
- 候选身份、来源和去重结果；
- 勾选、排除、删除和交接状态；
- 图谱上下文与缓存；
- 全文批次、下载结果和缺失清单；
- 当前阶段和任务状态。

同一主题的不同策略建议建立不同轮次，以便比较高召回与高精度。删除项目会把快照移入 `projects\_trash`，不会同时删除 PDF 和原始运行记录。

## 11. 数据、备份和升级

默认数据目录：

```text
%LOCALAPPDATA%\OpenPaper\data
```

主要子目录包括 `downloads`、`projects`、`runs`、`graph_cache`、`cnki`、`auth`、`logs` 和 `settings.json`。

升级前：

1. 等待任务结束；
2. 完全退出 OpenPaper；
3. 复制整个数据目录到受控备份位置；
4. 把新版本解压到新目录，不覆盖旧程序；
5. 启动新版本并核对项目库和设置。

数据目录包含研究资料和认证状态，不应直接上传公共云盘或随反馈包发送。

## 12. Sci-Hub 兼容回退边界

OpenPaper 内测版保留该兼容选项，但全新安装默认关闭。仅在用户主动启用后，它才可能在正常/OA 来源均失败时作为最后回退尝试；结果会单独标记，不能伪装成 OA 或出版社版。

如果不确定是否合规，应保持关闭。是否使用及如何处理结果由使用者根据所在地、机构和内容提供方规则自行判断。

## 13. 建议的研究习惯

- 每个项目开始前在外部记录数据库范围、日期和纳入排除标准。
- 英文与中文分别准备适合各自生态的概念组。
- 先小批试搜，再扩大结果数量。
- 对推荐与非推荐文献都做抽样检查。
- 小批量提交全文任务，便于定位失败来源。
- 项目结束时重开项目核对统计并备份数据。
